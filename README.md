# 屏幕划取翻译（ScreenTranslator）

常驻托盘的 Windows 小工具，用来翻译**选不中文字**的地方：游戏对话、PDF、图片、网页、视频字幕。

按一下快捷键，屏幕冻住，你框住想看的那块 → 译文弹在旁边；或者按另一个快捷键，
**整屏的字被翻好、直接盖在原文位置上**。

- 目标系统：Windows 10 (1903+) / Windows 11
- 技术栈：C# / .NET 9 / WPF + WinForms(NotifyIcon)
- 发布形态：单个自包含 exe（约 71 MB），目标机不需要装任何运行环境
- **程序不内置任何 API key**，用你自己的

---

## 两个入口，三条路线

| | 框选翻译 `Ctrl+Alt+Q` | 全屏翻译 `Ctrl+Alt+W` |
|---|---|---|
| 范围 | 你框住的那一块 | 整个屏幕 |
| 结果 | 弹在旁边的小窗里 | 原地盖在原文上 |
| 走哪条路 | 设置里二选一 | 固定：OCR 出坐标 + 多模态出译文 |

框选翻译可以选两条路，各有各的服务配置：

- **识文翻译** —— Windows 自带的文字识别先把字读出来，再交给文字模型翻译。
  认字在本机做，便宜；缺点是白底黑字之外的场景（游戏花体字、彩色背景、竖排日文）容易认错，
  而且一块区域里只会按一种语言来读。
- **看图翻译** —— 把框选的那张图直接发给能看图的模型，跳过认字。
  一张图里混着好几种语言也能一起翻。代价是每次都要联网发图。

**全屏翻译走的是混合模式，不是「看图翻译的整屏版」。** 多模态模型给不出可靠坐标——
你让它报坐标，它会编。所以这里让 OCR 只回答「字在屏幕的哪个位置」，让多模态回答
「这些字是什么意思」，截图会一起发过去让它纠正认错的字。

实测最能说明这个设计的一次：OCR 把两行日文读成了纯乱码
（`儆次 0 = 0 矿。今日儆 00 天氦 ℃ 矿。`），模型仍然返回了「早上好。今天天气真好。」——
因为它看得见图。反过来说，这条路上 OCR **认错字不要紧，框错了就全错**。

### 全屏翻译是一张快照

按一下出一张，画面一变就对不上了，Esc 关掉重按即可。**不是**一直挂着跟随画面变化的实时叠加。

看的时候可以：左键点一下看原图、按住空格对照、**拖一个框复制那几段**、Ctrl+C 复制全部、
Ctrl+S 或点「保存图片」存成 PNG。复制和保存都遵循**所见即所得**——正在看译文就是译文，
按住空格看原文时就是原文。

有三件事是这个做法本身的性质，不是 bug：译文和原文不一样长所以字号会缩、
压在图片/渐变上的字底衬是个纯色块（目标是看得清，不是看不出痕迹）、表格和分栏还原不了。

## 构建与运行

```powershell
# 开发时直接跑
dotnet run --project src\ScreenTranslator\ScreenTranslator.csproj

# 打包成单个 exe（输出到 .\dist\ScreenTranslator.exe）
.\publish.ps1
```

图标是脚本生成的，改了样式重新跑一次即可：

```powershell
.\tools\make-icon.ps1
```

首次使用：右键托盘图标 → 设置，在「框选翻译」页填一个服务的地址 / API Key / 模型，
点「测试连接」。想用看图或全屏，就在对应的栏里再填一个**支持看图**的模型
（如通义千问的 `qwen-vl-max-latest`、智谱的 `glm-4v-flash`）。

## 诊断命令

都不弹窗、不抢鼠标键盘，跑完写一份报告到 `%APPDATA%\ScreenTranslator\`。
带参数的形式**只用于传临时测试值**（命令行参数对同机其它进程可见），且不会碰你保存的配置。

```powershell
.\dist\ScreenTranslator.exe --selftest        # 框选对齐自检（换显示器或改缩放后值得重跑）
.\dist\ScreenTranslator.exe --testkey         # 文字翻译连通性 + 可用模型 + 流式分段数
.\dist\ScreenTranslator.exe --testvision      # 看图连通性，并挑出名字像是会看图的模型
.\dist\ScreenTranslator.exe --testsnapshot    # 整屏全流程；加 --dry 不联网不花钱
.\dist\ScreenTranslator.exe --testclipboard   # 复制是否成功 + 耗时

.\dist\ScreenTranslator.exe --testkey      <地址> <模型> <key>
.\dist\ScreenTranslator.exe --testvision   <地址> <模型> <key>
.\dist\ScreenTranslator.exe --testsnapshot <地址> <模型> <key>
```

几条值得单独说明的：

**`--selftest`** 验证的是「框的位置和截到的区域一定对得上」这条不变量：进程真的是
Per-Monitor-V2、虚拟桌面矩形覆盖全部显示器、遮罩窗口的物理像素矩形与之完全相等、
从冻屏位图裁出来的区域与直接截屏**逐像素一致**。

**`--testvision`** 会发一张写着 `Good morning. The sky is blue.` 的小图过去，并把模型
读回来的内容原样写进报告。**必须看这两行对不对得上**——不会看图的模型照样会答一句
像样的话，只看「状态：Success」会被骗过去。

**`--testsnapshot`** 输出两张图：`testsnapshot-blocks.png`（每段的框和编号）和
`testsnapshot.png`（覆盖效果）。**排版问题只能看图，报告里的数字看不出来。**
`--dry` 用等长占位文字代替译文，不联网不花钱，是调排版时该先跑的那个。

## 文件位置

| 用途 | 路径 |
|---|---|
| 配置 | `%APPDATA%\ScreenTranslator\config.json`（保存前会留一份 `.bak`） |
| 日志 | `%APPDATA%\ScreenTranslator\logs\yyyy-MM-dd.log`（保留 7 天） |
| 翻译历史 | `%APPDATA%\ScreenTranslator\history.json`（封顶 30 条，可关可清空） |
| 框选的截图 | 默认第一个非系统盘下的 `\ScreenTranslator\框选翻译\` |
| 整屏译文图 | 默认第一个非系统盘下的 `\ScreenTranslator\全屏翻译\`（不自动保存，手动存才有） |
| 开机自启 | 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `ScreenTranslator` |

默认**不用**系统「图片」文件夹：它在多数机器上被 OneDrive 接管，那会让每张截图都被上传。

### 关于你的 key

**不会明文落盘。** 用 Windows DPAPI 按当前用户账户加密后，以 base64 存在 `config.json` 的
`ApiKeyProtected` 字段里。把 `config.json` 复制到别的电脑或别的用户账户下是解不开的——
这是有意为之。三条路的 key 分开存，互相看不到。

翻译历史里是当时屏幕上的内容，所以它封顶 30 条、能在设置里关掉、也能一键清空。

配置、日志、截图、历史**全部在项目目录之外**，所以仓库里不可能混进这些。

## 关键实现说明

### 冻屏截图法

按下快捷键的瞬间先把整个虚拟桌面 `BitBlt` 成一张位图，再把这张位图铺在一个覆盖虚拟桌面
矩形的置顶窗口上供用户框选，松手后直接从这张位图里裁。选区坐标和位图坐标是同一套物理像素，
因此**不存在 DPI 换算，也就不可能出现「框的位置和截到的区域对不上」**，无论几块屏、缩放多少。
全屏翻译的覆盖层建在同一条不变量上——OCR 报的坐标就是位图坐标，直接画即可。

进程在 `app.manifest` 里声明 `PerMonitorV2`。这必须由清单完成——它要在原生启动的第一时间生效，
任何托管代码（包括 `Application.SetHighDpiMode`）都太晚了。因此项目里关掉了 WinForms 的
`WFO0003` 警告。

### 译文窗不抢焦点

结果小窗是 `WS_EX_NOACTIVATE`，永远拿不到键盘焦点——不然它会抢走游戏或编辑器的输入。
代价是 Esc 和「点别处关闭」不能走常规的键盘事件，改用轮询实现；
**故意不用低级键盘钩子**（钩子卡住会拖慢全系统输入），也不用 `RegisterHotKey`（会吞掉 Esc）。

### 单实例

命名互斥体 `Local\ScreenTranslator.SingleInstance.v1` 决定谁是主实例；后启动的实例通过命名管道
`ScreenTranslator.Ipc.v1` 把意图交给主实例后自行退出。所以重复双击 exe 会唤起已有实例的
设置窗口，而不是开出第二个托盘图标。

### 可换引擎

OCR 和翻译都按接口设计（`IOcrProvider` / `ITranslator`）。三条路线各自持有一整套设置
（服务 / 超时 / 图片边长 / 保存目录 / 小窗 / 历史），互不共享——它们指向不同厂商、
快慢差一个量级、产出的文件也不是一类东西，一个共享的「超时」总有两条是错的。

文字翻译和看图翻译共用同一个 OpenAI 兼容适配器，靠一个开关分流。不是为了省事：
流式读取、断线抢救、HTTP 错误映射这三块要是抄成两份，早晚会只修好一边。

预设里的 DeepSeek / 通义千问 / 智谱 / Kimi / OpenAI 都走这一个适配器——
换服务商只是换 base URL + 模型 + key，不涉及代码。

### 代理

翻译请求默认走系统代理（访问境外服务通常需要）。但**回环地址（127.0.0.1 / localhost）
强制不走代理** —— 接本地模型（Ollama、LM Studio 等）时，请求被代理吞掉会得到一个
毫无意义的 502，极难排查。

## 已知限制

- **全屏独占游戏**：`BitBlt` 可能截到黑屏，置顶小窗也可能被吃掉。需要换成
  Windows.Graphics.Capture 才能解决。
- **OCR 质量**：Windows 内置引擎对白底黑字印刷体尚可，对彩色背景、竖排日文、
  游戏花体字很差——这正是「看图翻译」存在的理由。
- **自动语种判定**：纯启发式，短文本和日英混排是弱项。可以在设置里锁定为固定语言。
- **多显示器**：多屏路径按正确方式实现了，但开发机只有一块屏，未能亲手验证。
